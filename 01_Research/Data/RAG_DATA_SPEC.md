# แบบจำลองข้อมูลสำหรับ RAG ของ FutureMe AI

> จุดประสงค์: แยก “ข้อมูลที่เปลี่ยนตามเวลา” ออกจาก “ความรู้ทั่วไป” และแยก “ข้อเท็จจริง” ออกจาก “สมมติฐานออกแบบ”  
> ข้อแนะนำหลัก: MVP ยังไม่ต้องทำ LoRA เพื่อจำหลักสูตร ใช้ RAG + rule engine + scoring ที่อธิบายได้ก่อน

## 1. ชุดข้อมูลที่ต้องมี

### A. ผู้เรียน (`learner_profile`)

- ระดับชั้น/วุฒิปัจจุบัน
- วิชาที่ชอบและไม่ชอบ พร้อมเหตุการณ์ตัวอย่าง
- กิจกรรมที่ทำแล้วมีพลัง/หมดพลัง
- ทักษะที่มีหลักฐาน เช่น ผลงาน โครงงาน งานอาสา
- ข้อจำกัด: ค่าใช้จ่าย พื้นที่ สุขภาพ ภาษา เวลาที่มี
- เป้าหมายและระดับความมั่นใจ
- ความยินยอม อายุผู้ใช้ และผู้มีสิทธิทบทวนข้อมูล

ข้อมูลละเอียดของผู้เรียนไม่ควรถูกนำไปฝึกโมเดลโดยอัตโนมัติ

### B. อาชีพ (`occupation`)

- `occupation_id`, ชื่อไทย/อังกฤษ, คำพ้อง
- งานที่ทำจริง (`tasks`)
- ทักษะ ความรู้ ความสนใจ ลักษณะงาน และบริบทการทำงาน
- คุณวุฒิ/ใบอนุญาตที่ “จำเป็น” แยกจากสิ่งที่ “มักพบ”
- แหล่ง O*NET/ESCO/TPQI และเวอร์ชัน
- ความเสี่ยง/ข้อจำกัดของข้อมูลต่างประเทศเมื่อใช้กับไทย

### C. หลักสูตร (`program`)

- สถาบัน คณะ หลักสูตร ระดับวุฒิ ที่ตั้ง ค่าใช้จ่ายโดยประมาณ
- เนื้อหา/ผลลัพธ์การเรียนรู้
- อาชีพปลายทางหลายรายการพร้อมชนิดความสัมพันธ์
- `admission_cycle`, รอบรับ, คะแนน/แฟ้ม/คุณสมบัติ, วันหมดอายุข้อมูล
- URL หน้าหลักสูตรและหน้ารับสมัครโดยตรง

### D. เส้นทาง (`pathway_edge`)

เก็บเป็น edge เพื่อประกอบ roadmap:

```json
{
  "from_id": "upper_secondary",
  "to_id": "program:computer_science:x:2570",
  "relation": "eligible_path",
  "required": false,
  "conditions": ["เกณฑ์ของหลักสูตรปี 2570"],
  "evidence_ids": ["src_mytcas_program_x_2570"]
}
```

### E. หลักฐาน (`source_evidence`)

```json
{
  "evidence_id": "src_tdri_human_capital_2025",
  "publisher": "TDRI",
  "title": "การพัฒนาทุนมนุษย์ไทย",
  "source_url": "https://tdri.or.th/2025/09/thailand-human-capital-development/",
  "published_at": "2025-09",
  "retrieved_at": "2026-07-24",
  "claim_text": "ผู้มีการศึกษาสูงกว่ามัธยมปลาย 56% ทำงานไม่ตรงสาขา",
  "scope": "Thailand; higher than upper-secondary education",
  "status": "verified",
  "license": "check_source_terms",
  "valid_until": null
}
```

## 2. การแบ่ง index

อย่าใส่ทุกอย่างใน vector index เดียว:

1. `stable_knowledge`: นิยามอาชีพ ทักษะ งาน และกรอบสัมภาษณ์
2. `program_catalog`: หลักสูตรและผลลัพธ์การเรียนรู้
3. `admission_rules`: เกณฑ์ TCAS/HSCES ที่มีปีและวันหมดอายุ
4. `labor_market`: สถิติและประกาศงานที่มีช่วงเวลา/ขอบเขต
5. `policy_and_platform`: NDLP/DEEP/AIS และเงื่อนไขการเชื่อมต่อ
6. `quarantine_unverified`: ข้อมูลที่ยังตรวจไม่ได้; ห้ามค้นใน production

ใช้ metadata filter ก่อน semantic search เช่น ปีการศึกษา ระดับวุฒิ จังหวัด ภาษา และสถานะข้อมูล

## 3. Pipeline แนะนำ

1. ดึงข้อมูลจากแหล่งตรง
2. เก็บไฟล์ดิบแบบ immutable พร้อม checksum
3. แยกเป็น claim ขนาดเล็ก ไม่ chunk ข้ามหลายหัวข้อ
4. ให้คนตรวจ source-to-claim และกำหนด `verified/conditional/unverified`
5. สร้าง embeddings และ index เฉพาะระเบียนที่ผ่าน
6. คำนวณ recommendation ด้วยกฎและคะแนนที่อธิบายได้
7. ให้ LLM เขียนคำอธิบายโดยอ้าง evidence ID
8. แสดง “เหตุผล–ข้อจำกัด–ทางเลือกสำรอง” และให้เด็กแก้ข้อมูล/ไม่เห็นด้วยได้

## 4. Recommendation score

แยกคะแนนอย่างน้อย 5 มิติ:

- Interest fit
- Evidence-backed skill fit
- Work-context fit
- Constraint feasibility
- Education/admission readiness

ไม่ควรรวมเป็นคำตัดสินเดียวโดยไม่แสดงองค์ประกอบ และห้ามเขียนว่า “AI รู้ว่าคุณเหมาะกับอาชีพนี้” ควรเขียนว่า “จากข้อมูลที่ให้มา เส้นทางนี้ควรทดลองสำรวจต่อ เพราะ…”

## 5. LoRA ใช้เมื่อไร

ยังไม่ใช้ LoRA เพื่อสอนข้อเท็จจริงเรื่องหลักสูตร อาชีพ หรือรอบรับสมัคร เพราะข้อมูลเปลี่ยนและอัปเดตผ่าน RAG ได้ง่ายกว่า LoRA เหมาะเมื่อมีตัวอย่างคุณภาพสูงจำนวนมากสำหรับ:

- รูปแบบการสนทนาภาษาไทยที่ปลอดภัยและไม่ชี้นำ
- การสกัดข้อมูลจากบทสัมภาษณ์เป็น schema เดียวกัน
- การเขียนเหตุผลของคำแนะนำตาม rubric

ก่อน LoRA ควรมีชุดตัวอย่างที่ผู้เชี่ยวชาญตรวจแล้ว ชุด test ที่ไม่ปนกับ train และ baseline เปรียบเทียบกับ prompting/RAG หากยังไม่มีข้อมูลดังกล่าว ให้ทำ prompt + structured output + evaluation ก่อน

## 6. การประเมินระบบ

- Retrieval: source recall, citation precision, freshness
- Mapping: ความถูกต้องของ occupation–skill–program edges
- Recommendation: counselor agreement, student usefulness, diversity of options
- Safety: อัตราคำแนะนำเกินหลักฐาน, การตีตรา, bias ตามเพศ/ฐานะ/พื้นที่
- Product: เด็กเข้าใจเหตุผลหรือไม่ และลงมือทดลองเส้นทางต่อได้หรือไม่

ชุดทดสอบควรมีทั้งนักเรียนที่ยังไม่รู้ความสนใจ ผู้เรียนสายอาชีพ GED/สกร./Homeschool เด็กต่างจังหวัด ผู้มีข้อจำกัดด้านงบประมาณ และเคสที่ข้อมูลไม่พอซึ่งระบบต้องยอมรับว่า “ยังสรุปไม่ได้”
