# 17 — อภิธานศัพท์ (Glossary) English–Thai

> วันที่ตรวจสอบข้อมูล: 21 กรกฎาคม 2026
> รูปแบบ: **English (ไทย)** — ความหมายสั้น + ตัวอย่างการใช้งาน

| ศัพท์ | ความหมายสั้น (ไทย) | ตัวอย่างการใช้งาน |
|-------|--------------------|-------------------|
| **Large Language Model — LLM (โมเดลภาษาขนาดใหญ่)** | โมเดลภาษาพารามิเตอร์มหาศาล (หลายหมื่น-แสนล้าน) | GPT/Llama-70B ใช้ทำงานทั่วไปกว้าง |
| **Small Language Model — SLM (โมเดลภาษาขนาดเล็ก)** | โมเดล ~1–9B ที่รันบนฮาร์ดแวร์ทั่วไปได้ | รัน Qwen2.5-7B บน GPU 8GB สำหรับ RAG |
| **Retrieval (การดึงข้อมูล)** | ค้นเอกสารที่เกี่ยวข้องจากฐานความรู้ | ค้น chunk top-5 จาก vector DB |
| **Augmentation (การเสริมบริบท)** | นำข้อมูลที่ค้นได้แนบเข้า prompt | ใส่ chunk เข้า context ก่อนให้ตอบ |
| **Generation (การสร้างคำตอบ)** | โมเดลสร้างข้อความคำตอบ | ตอบคำถามจาก context ที่ให้ |
| **RAG (Retrieval-Augmented Generation)** | ค้นก่อนตอบ = "สมองที่สอง" | ถาม-ตอบเอกสารองค์กรพร้อม citation |
| **Embedding (เวกเตอร์ความหมาย)** | แปลงข้อความเป็นเวกเตอร์ตัวเลข | ใช้ BGE-M3 แปลงประโยคไทย |
| **Vector (เวกเตอร์)** | ชุดตัวเลขแทนความหมายข้อความ | เวกเตอร์ 1024 มิติ |
| **Vector Database (ฐานข้อมูลเวกเตอร์)** | เก็บ+ค้นเวกเตอร์เร็ว | Chroma/Qdrant เก็บ embedding |
| **Chunk (ชิ้นข้อความ)** | ส่วนย่อยของเอกสารที่ตัดไว้ค้น | ตัดเอกสารเป็นชิ้น ~500 token |
| **Chunking (การแบ่งชิ้น)** | กระบวนการตัดเอกสารเป็น chunk | semantic/parent-child chunking |
| **Overlap (การซ้อนทับ)** | ให้ chunk ซ้อนกันกันบริบทขาด | overlap 15% ระหว่าง chunk |
| **Context (บริบท)** | ข้อความที่ให้โมเดลใช้ประกอบคำตอบ | context = chunk ที่ค้นได้ |
| **Context Window (หน้าต่างบริบท)** | ปริมาณ token สูงสุดที่โมเดลรับได้ | 8K/128K token |
| **Tokenization (การแบ่งโทเคน)** | แบ่งข้อความเป็นหน่วยย่อย (token) | ไทยกิน token ต่อคำมากกว่าอังกฤษ |
| **Token (โทเคน)** | หน่วยย่อยที่โมเดลประมวลผล | นับ token เพื่อคุมต้นทุน |
| **Retriever (ตัวค้นคืน)** | โมดูลรับคำถาม→คืน chunk | hybrid retriever (semantic+BM25) |
| **Reranker (ตัวจัดอันดับใหม่)** | cross-encoder จัดอันดับผลค้นให้แม่นขึ้น | BGE-reranker เลือก top-3 |
| **Hybrid Search (การค้นแบบผสม)** | รวม semantic + keyword (BM25) | ช่วยจับชื่อเฉพาะ/เลขเอกสารไทย |
| **BM25** | อัลกอริทึมค้นแบบ keyword/sparse | จับคำตรงตัวในเอกสาร |
| **Semantic Search (การค้นเชิงความหมาย)** | ค้นด้วยความคล้ายความหมาย | เจอคำพ้องแม้ไม่ตรงคำ |
| **Cosine Similarity (ความคล้ายโคไซน์)** | วัดมุมระหว่างเวกเตอร์ | metric นิยมใน RAG |
| **Hallucination (การแต่งข้อมูล)** | โมเดลตอบผิด/มั่วอย่างมั่นใจ | อ้างระเบียบที่ไม่มีจริง → ต้องวัด/กัน |
| **Faithfulness (ความซื่อต่อหลักฐาน)** | คำตอบยึดกับ context แค่ไหน | metric หลักลด hallucination |
| **Citation (การอ้างอิงแหล่ง)** | ระบุที่มาของคำตอบ | `[แหล่ง: ระเบียบ_2567.pdf หน้า 12]` |
| **Fine-tuning (การปรับแต่งโมเดล)** | เทรนต่อด้วยข้อมูลเฉพาะ | ปรับสไตล์ตอบเป็นภาษาราชการ |
| **PEFT (Parameter-Efficient Fine-Tuning)** | ปรับพารามิเตอร์ส่วนน้อย | LoRA/QLoRA |
| **LoRA (Low-Rank Adaptation)** | เพิ่ม adapter low-rank เทรนแทนทั้งโมเดล | เทรน adapter บน 7B ด้วย VRAM น้อย |
| **QLoRA** | LoRA บนโมเดล 4-bit (NF4)+double quant | fine-tune 7B บน Colab T4 |
| **Quantization (การลดความละเอียด)** | ลดบิตน้ำหนักเพื่อประหยัดหน่วยความจำ | 4-bit ลด VRAM ~4 เท่า |
| **NF4 (NormalFloat4)** | ชนิดข้อมูล 4-bit เหมาะการกระจายน้ำหนัก | ใช้ใน QLoRA |
| **Adapter (อะแดปเตอร์)** | โมดูลเล็กเสียบปรับพฤติกรรมโมเดล | LoRA adapter ~ไม่กี่ MB |
| **Rank (แรงก์ / r)** | ขนาด low-rank ของ adapter | r=8/16/32 |
| **Alpha (อัลฟา)** | สเกลของ LoRA adapter | มักตั้ง = r หรือ 2r |
| **Overfitting (โอเวอร์ฟิต)** | จำ training จน generalize แย่ | ใช้ validation/early stopping |
| **Catastrophic Forgetting (การลืมร้ายแรง)** | เทรนใหม่จนลืมของเดิม | LoRA ช่วยลดเพราะ freeze base |
| **Inference (การอนุมาน/ใช้งานโมเดล)** | รันโมเดลเพื่อสร้างผลลัพธ์ | เสิร์ฟด้วย vLLM/Ollama |
| **Latency (ความหน่วง)** | เวลาต่อคำตอบ | วัด p95 latency |
| **Throughput (ปริมาณงานต่อเวลา)** | จำนวนคำตอบ/token ต่อวินาที | tokens/s ของ GPU |
| **GPU (หน่วยประมวลผลกราฟิก)** | ฮาร์ดแวร์เร่ง AI | RTX 4090/A10/L4 |
| **VRAM (หน่วยความจำ GPU)** | RAM บน GPU | 7B 4-bit ~5–8GB VRAM |
| **Agent (เอเจนต์)** | LLM ที่ตัดสินใจใช้ tool เอง | Agentic RAG ค้นหลายรอบ |
| **Pipeline (ไปป์ไลน์)** | ลำดับขั้นการประมวลผลต่อเนื่อง | ingest→embed→search→generate |
| **Prompt Engineering** | ออกแบบคำสั่ง/ตัวอย่างใน prompt | สั่ง "ตอบจาก context เท่านั้น" |
| **Prompt Injection** | คำสั่งอันตรายแฝงในอินพุต/เอกสาร | เอกสารสั่งโมเดลเปิดเผยข้อมูล |
| **RBAC (Role-Based Access Control)** | คุมสิทธิ์ตามบทบาท | หัวหน้าเห็นเอกสารมากกว่าพนักงาน |
| **Metadata (ข้อมูลกำกับ)** | ข้อมูลอธิบาย chunk (ไฟล์/หน้า/สิทธิ์) | ใช้ทำ filter + citation |
| **OCR (การรู้จำอักขระจากภาพ)** | แปลงเอกสารสแกนเป็นข้อความ | Typhoon OCR อ่าน PDF สแกนไทย |
| **Model Serving (การเสิร์ฟโมเดล)** | ให้บริการโมเดลผ่าน API | vLLM/TGI/Ollama |
| **Precision@K / Recall@K** | เมตริกวัดคุณภาพการค้น | Recall@5 ≥ 0.8 |
| **MRR / NDCG** | เมตริกวัดอันดับผลค้น | ผลถูกอยู่บนสุดไหม |
