# 02 — โมเดลภาษาขนาดเล็ก (Small Language Models)

> วันที่ตรวจสอบข้อมูล: 21 กรกฎาคม 2026
> ⚠️ โมเดลออกใหม่เร็วมาก ตัวเลข/เวอร์ชัน/ลิขสิทธิ์ในไฟล์นี้เป็นข้อมูล ณ วันตรวจสอบ — **ต้องยืนยันกับ Model Card ทางการก่อนใช้จริงเสมอ** และ **ห้ามสรุปว่าโมเดลใด "ดีที่สุด" โดยไม่มี benchmark กับข้อมูลของคุณเอง**

## 1. Small Language Model (SLM) คืออะไร

ไม่มีนิยามตายตัว โดยทั่วไปหมายถึงโมเดลภาษาที่มีพารามิเตอร์ "เล็กพอจะรันบนฮาร์ดแวร์ทั่วไป/การ์ดใบเดียว" — ในทางปฏิบัติมักหมายถึงช่วง **~1B ถึง ~9B พารามิเตอร์** (บางคนรวมถึง ~13B) เทียบกับ LLM ระดับ 70B–600B+

**เหมาะกับงานประเภทใด**
- งานเฉพาะทางที่นิยามชัด (ถาม-ตอบเอกสาร, สรุป, จัดหมวด, สกัดข้อมูล) — โดยเฉพาะเมื่อมี **RAG** ป้อนความรู้ให้
- งานที่ต้องการ latency ต่ำ, ต้นทุนคุมได้, deploy ในองค์กร
- งานที่ปรับแต่งด้วย LoRA/QLoRA บนการ์ดเดียว

**ไม่เหมาะ**
- reasoning หลายขั้นที่ซับซ้อนมาก, ความรู้ทั่วไปกว้างลึก, งาน open-ended ที่ไม่มีเอกสารอ้างอิง — งานเหล่านี้โมเดลใหญ่ยังได้เปรียบ

## 3. เกณฑ์เปรียบเทียบเชิงลึก (ที่ต้องพิจารณาก่อนเลือก)

- **ขนาด/พารามิเตอร์** → กำหนด VRAM และความเร็ว
- **Context length** → จุ chunk ได้กี่ชิ้น (ระวัง tokenizer ไทย, ดู `01_...`)
- **ความสามารถไทย** → ดู ThaiExam/SEA-HELM + **ทดสอบกับเอกสารของคุณเอง**
- **Instruction following** → สำคัญมากสำหรับ RAG (ต้องเชื่อฟังคำสั่ง "ตอบจาก context เท่านั้น")
- **Quantization** → รองรับ GGUF (llama.cpp/Ollama) หรือ 4-bit (bitsandbytes) ไหม
- **LoRA/QLoRA** → base architecture รองรับ PEFT ไหม (ส่วนใหญ่ Llama/Qwen/Gemma รองรับ)
- **RAM/VRAM** → ดูตารางประมาณการด้านล่าง
- **ความเร็วตอบ (tokens/s)** → ขึ้นกับฮาร์ดแวร์+quant
- **เหมาะกับ RAG** → instruction-following + faithfulness ดี, context พอ
- **เชิงพาณิชย์** → license

## 4. ประมาณการทรัพยากร (ค่าประมาณ — ขึ้นกับ quant/context/runtime)

| ขนาดโมเดล | FP16 (VRAM โดยประมาณ) | 4-bit quant (VRAM โดยประมาณ) | รันบน CPU ได้ไหม |
|-----------|----------------------|------------------------------|------------------|
| 1–1.5B | ~3–4 GB | ~1–2 GB | ได้ (ค่อนข้างลื่น) |
| 3B | ~6–8 GB | ~2.5–4 GB | ได้ (พอใช้) |
| 7–9B | ~14–18 GB | ~5–8 GB | ได้แต่ช้า (ควรมี RAM ≥16GB) |

> ⚠️ เป็นค่าประมาณสำหรับ **inference** เท่านั้น การ **เทรน/LoRA** ใช้มากกว่านี้ (ดู `07_...`) ตัวเลขจริงขึ้นกับ context length, batch, KV cache และ runtime (llama.cpp, vLLM, transformers)

> เป็น **ข้อเสนอแนะเชิงออกแบบ** ต้องยืนยันด้วย benchmark ของคุณเอง

| สภาพแวดล้อม | ข้อเสนอแนะเริ่มต้น | เหตุผล |
|-------------|-------------------|--------|
| **เครื่องไม่มี GPU (CPU only)** | Typhoon2 1–3B / Qwen2.5-1.5B/3B / Gemma 3 1B–4B (GGUF ผ่าน Ollama/llama.cpp) | เล็กพอรัน CPU, Gemma ประหยัด RAM |
| **GPU เล็ก (8–12GB)** | Qwen2.5-7B / Gemma 3 4B / OpenThaiGPT-7B (4-bit) | พอดี VRAM, คุณภาพดีขึ้นชัด |

## 6. รันไทม์สำหรับเสิร์ฟ SLM (อ้างอิงสั้น)

- **Ollama / llama.cpp** — ง่ายสุด สำหรับ local/CPU/GGUF (prototype)
- **vLLM / TGI (Text Generation Inference)** — throughput สูง สำหรับ GPU/production
- **Hugging Face `transformers`** — ยืดหยุ่นสุด เหมาะทดลอง/เทรน

> **ข้อควรระวัง:** ก่อน commit เลือกโมเดล ให้สร้าง "ชุดคำถามภาษาไทย 20+ ข้อ" (ดู `10_...`) แล้ววัด faithfulness/accuracy กับเอกสารจริง อย่าเลือกตามความนิยมอย่างเดียว
