# 12 — การวางแผนต้นทุนและทรัพยากร (Cost & Resource Planning)

> วันที่ตรวจสอบข้อมูล: 21 กรกฎาคม 2026
> ⚠️ **คำเตือนสำคัญเรื่องตัวเลข:** ราคาคลาวด์/GPU/API **เปลี่ยนบ่อยและต่างตามภูมิภาค/ผู้ให้บริการ/โปรโมชัน** ตัวเลขด้านล่างเป็น **ช่วงประมาณการเชิงลำดับขนาด (order-of-magnitude)** เพื่อวางแผน ไม่ใช่ราคาจริง ณ ปัจจุบัน **ต้องเปิดหน้า pricing ทางการของผู้ให้บริการเพื่อยืนยันก่อนตัดสินใจเสมอ** (สกุลเงินอ้างอิง: USD ต่อเดือน เว้นระบุอย่างอื่น)

## 1. องค์ประกอบต้นทุน

| องค์ประกอบ | โมเดลราคา | ปัจจัยที่ทำให้เปลี่ยน |
|-----------|-----------|------------------------|
| **Local CPU** | ลงทุนฮาร์ดแวร์ครั้งเดียว + ค่าไฟ | สเปกเครื่อง, ค่าไฟท้องถิ่น |
| **Consumer GPU** (เช่น RTX 4090) | ลงทุนครั้งเดียว (หลักหมื่น–แสนบาท) + ค่าไฟ | รุ่นการ์ด, ราคาตลาด |
| **Google Colab** | ฟรี (จำกัด) / Pro รายเดือน | ระดับ GPU (T4/L4/A100), เวลา |
| **Cloud GPU** (RunPod/Vast/Lambda/AWS/GCP) | รายชั่วโมง/รายเดือน | ชนิด GPU, on-demand vs spot, region |
| **Managed Vector DB** (Qdrant/Zilliz/Weaviate/Pinecone cloud) | ตามขนาด/ปริมาณ query | จำนวนเวกเตอร์, มิติ, QPS |
| **Model API** (เรียกภายนอก) | ต่อ token (in/out) | ปริมาณ token (ไทยกิน token เยอะ!), โมเดล |
| **Storage** (object/DB) | ต่อ GB/เดือน + egress | ขนาดเอกสาร, backup |
| **Embedding** | API ต่อ token หรือ compute (self-host) | จำนวน chunk, ความถี่ reindex |
| **Monitoring/Observability** | ฟรี(self-host) หรือ SaaS | ปริมาณ trace/log |

> **จุดที่คนมองข้าม:** ภาษาไทยใช้ token ต่อข้อความมากกว่าอังกฤษ (ดู `01_...`) → **ต้นทุน API แบบต่อ token ของงานไทยมักสูงกว่าที่ประเมินจาก "จำนวนคำ"** ทดสอบ tokenizer จริงก่อนประเมิน

## 2. สามระดับงบประมาณ (ประมาณการเชิงลำดับขนาด)

> ทุกตัวเลขเป็น **ค่าประมาณเพื่อเปรียบเทียบสัดส่วน** ไม่ใช่ใบเสนอราคา — ตรวจสอบราคาจริงจากผู้ให้บริการ (วันที่ตรวจสอบราคาจริงต้องบันทึกเมื่อคุณไปเปิดดู)

### 2.1 งบต่ำ (Prototype / เรียนรู้) — เป้าหมาย: พิสูจน์แนวคิด
| รายการ | ทางเลือก | ต้นทุนโดยประมาณ |
|--------|----------|------------------|
| Compute | เครื่องที่มีอยู่ (CPU) หรือ Colab ฟรี/Pro | ~0 หรือ ~$10–12/เดือน (Colab Pro) |
| โมเดล | SLM 3–7B GGUF ผ่าน Ollama (local) | ฟรี (โอเพนซอร์ส) |
| Vector DB | Chroma/FAISS local | ฟรี |
| Storage | ดิสก์เครื่อง/โฟลเดอร์ | ฟรี |
| Monitoring | log ไฟล์/console | ฟรี |
| **รวม** | | **~$0–15/เดือน** |

### 2.2 งบปานกลาง (ทีมวิจัย/มหาวิทยาลัย) — เป้าหมาย: ใช้จริงหลายผู้ใช้
| รายการ | ทางเลือก | ต้นทุนโดยประมาณ |
|--------|----------|------------------|
| Compute | Cloud GPU 1 ตัว (เช่น L4/A10, on-demand บางเวลา หรือ spot) | ~$150–600/เดือน (ขึ้นกับชั่วโมงรัน) |
| โมเดล | SLM 7–9B self-host (vLLM) | ฟรี (รวมใน compute) |
| Vector DB | Qdrant self-host หรือ managed tier เล็ก | ฟรี–$100/เดือน |
| Storage | object storage + Postgres | ~$10–50/เดือน |
| Monitoring | Prometheus/Grafana self-host | ~ค่า compute เล็กน้อย |
| **รวม** | | **~$200–800/เดือน (ประมาณ)** |

> เคล็ด: ปิด GPU เมื่อไม่ใช้ (schedule) หรือใช้ spot/preemptible ลดค่า compute ได้มาก แต่แลกกับความเสถียร

### 2.3 งบ Production (องค์กร) — เป้าหมาย: ผู้ใช้จำนวนมาก + SLA
| รายการ | ทางเลือก | ต้นทุนโดยประมาณ |
|--------|----------|------------------|
| Compute | GPU node pool (autoscale, A10/L4/A100) | $1,000s+/เดือน (ตาม concurrency) |
| Vector DB | Qdrant/Milvus cluster หรือ managed | $100s–1,000s/เดือน |
| Storage + DB (HA) | object + Postgres HA + backup | $100s/เดือน |
| Observability/Security | logging, tracing, secret mgr | $100s/เดือน |
| **รวม** | | **หลักพัน USD+/เดือน (ประมาณ, แปรผันตามโหลด)** |

## 3. Self-host vs API (การตัดสินใจต้นทุน)

| | Self-host (open model) | Model API |
|--|------------------------|-----------|
| ต้นทุนคงที่ | สูง (GPU/ops) | ต่ำ |
| ต้นทุนแปรผัน | ต่ำต่อ query | สูง (ต่อ token, ไทยแพงกว่า) |
| คุ้มเมื่อ | ปริมาณสูง/ต้องคุมข้อมูล | ปริมาณต่ำ/ต้นแบบ/ไม่มีข้อมูลลับ |
| ความเป็นส่วนตัว | สูง | ต่ำ (ดู `11_...`) |

> **ข้อเสนอแนะ:** ประเมิน **break-even** — ถ้า query/เดือนสูงและข้อมูลลับ → self-host คุ้มกว่าในระยะยาว; ถ้าปริมาณต่ำ/ยังทดลอง → API ประหยัดกว่าตอนเริ่ม แต่ระวัง cost ไต่ขึ้นเร็วเมื่อ scale

## 4. วิธีทำ Cost Model ของคุณเอง (แนะนำ)
1. วัด **token เฉลี่ยต่อคำถาม** จริง (prompt+context+คำตอบ) ด้วย tokenizer ที่จะใช้
2. ประมาณ **query/เดือน**
3. คูณกับราคา (API) หรือคำนวณ **GPU-hours** (self-host) จาก throughput ที่วัดได้
4. บวก vector DB + storage + embedding (reindex) + monitoring
5. เผื่อ overhead 20–40% และทำ 3 scenario (ต่ำ/คาด/สูง)
6. **บันทึกวันที่ตรวจราคาและ URL หน้า pricing** ทุกครั้ง

## 5. เงื่อนไขที่ทำให้ราคาเปลี่ยน (ต้องระบุในรายงานจริง)
- ผู้ให้บริการปรับราคา / โปรโมชันหมดอายุ
- region / ค่า egress (โอนข้อมูลออก)
- on-demand vs spot/reserved
- ราคา GPU ตลาด (ขาด/ล้น)
- ปริมาณการใช้จริง vs ประมาณการ (โดยเฉพาะ token ไทย)
- อัตราแลกเปลี่ยน USD/THB
