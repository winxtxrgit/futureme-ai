## 2.1 วงจรหลัก

```
คำตอบของผู้เรียน
   ↓
[1] อัปเดตหลักฐาน        evidence[dimension][facet] += (response, weight)
   ↓
[2] อัปเดตความมั่นใจ      confidence[d] = coverage × consistency
   ↓
[3] ตรวจความขัดแย้ง       contradiction detector → ถ้าเจอ เข้าคิวคำถามคลี่คลาย
   ↓
[4] ตรวจเงื่อนไขหยุด      ถ้าเข้าเงื่อนไข → จบ
   ↓
[5] เลือกคำถามถัดไป       จากคิวที่จัดลำดับด้วยกฎ §2.4
   ↓
[6] ตัดงบ                 budget[dimension][facet][probeType] -= 1
   ↓
วนกลับ
```

ขั้นที่ **[6] คือสิ่งที่ทำให้วนไม่จบเป็นไปไม่ได้** ดู [`05-stopping-rules.md`](05-stopping-rules.md)

## 2.2 สภาวะของระบบ (state)

```ts
interface AssessmentState {
  answered: Array<{ itemId: string; value: 1|2|3|4|5; at: number }>;

  // ชั้น A — ชั้นเดียวที่ให้คะแนนเส้นทาง
  evidence: Record<Dimension, FacetEvidence[]>;   // 6 มิติ
  rescaled: Record<Dimension, number>;            // 0..1 — เรียก rescaled ไม่ใช่ standardized
  confidence: Record<Dimension, number>;          // 0..1
  dispersion: Record<Dimension, number>;          // ความไม่ลงรอยภายในมิติ

  // ชั้น B–G — ไม่เข้าคะแนน
  selfEfficacy: Partial<Record<Dimension, number>>;
  values: Partial<Record<WorkValue, number>>;
  formatPreference: Partial<Record<"hands_on"|"abstract"|"people"|"solo", number>>;
  environment: Partial<Record<EnvKey, number>>;
  barriers: BarrierNote[];        // แสดงแยก ไม่หักคะแนน
  readiness: 1|2|3|4;             // CIP — ปรับงบคำถาม

  // การควบคุมการไหล
  branch: Record<Dimension, "open"|"deep"|"deprioritised"|"pruned">;
  budget: Record<string, number>;         // key = `${dim}.${facet}.${probeType}`
  pending: QueuedItem[];                  // คิวที่จัดลำดับแล้ว
  openContradictions: Contradiction[];
  exploreQuota: number;                   // §2.7
  asked: Set<string>;                     // กันถามซ้ำ
}
```

**หมายเหตุคำศัพท์** `rescaled` คือ `(x−1)/4` ซึ่งเปลี่ยนหน่วยจาก 1–5 เป็น 0–1 เท่านั้น
รายงานตรวจสอบเชิงจิตมิติชี้ว่า **ห้ามเรียกสิ่งนี้ว่าคะแนนมาตรฐาน** เพราะไม่ใช่ norm score ไม่ใช่ percentile
ถ้าวันหนึ่งต้องการเทียบกับประชากร ต้องสร้าง norms แยก

## 2.3 ความมั่นใจ — คำนวณอย่างไร

ความมั่นใจ **ไม่ใช่คะแนน** และไม่ใช่ค่าที่มาจาก IRT (เรายังไม่มีคลังที่ปรับเทียบ ดู §2.6)
เป็นค่าที่ประกอบจากสองสิ่งที่วัดได้ตรง ๆ และอธิบายให้คนอ่านเข้าใจได้

```
confidence[d] = coverage[d] × consistency[d]
```

### coverage — ถามครอบคลุมพอไหม

```
coverage[d] = min(1, Σ (diagnosticWeight ของข้อที่ตอบใน d) / targetWeight)
```

- `diagnosticWeight` ต่อข้อ: L1 = 0.5 · L2 = 1.0 · L3 = 1.0 · L4 = 0.8 · L5 = 0.6
- `targetWeight` = 3.0 (เทียบเท่าข้อ L2 สามข้อ)
- **เหตุผลที่ตั้ง 3** เพราะต่ำกว่าสามข้อคำนวณการกระจายไม่ได้เลย
  และรายงานตรวจสอบระบุเป็นข้อวิกฤตว่า "ค่าเฉลี่ยของหนึ่งข้อก็คือคำตอบข้อนั้น"
- ข้อจาก **facet ที่ยังไม่เคยถาม** ได้น้ำหนักเต็ม · facet ซ้ำได้ครึ่งเดียว
  เพราะการถามเรื่องเดิมสามครั้งไม่ได้เพิ่มความครอบคลุม

### consistency — คำตอบในมิติเดียวกันไปทางเดียวกันไหม

```
consistency[d] = 1 − (sd ของคำตอบใน d / sdMax)      โดย sdMax = 2.0
```

`sd` คือส่วนเบี่ยงเบนมาตรฐานของคำตอบดิบ (สเกล 1–5) ในมิตินั้น
`sdMax = 2.0` คือค่าที่เกิดเมื่อคำตอบกระจายไปสองปลายสุด

### เกณฑ์ที่ใช้ตัดสินใจ

| ช่วง | ความหมาย | ระบบทำอะไร |
|---|---|---|
| < 0.40 | ต่ำ | ถามต่อในมิตินี้ ใช้ข้อ L2 ที่ยังไม่แตะ facet |
| 0.40–0.74 | กลาง | ถามข้อยืนยันแบบเจาะจง (L4) หรือ facet ที่ยังว่าง |
| ≥ 0.75 | สูง | หยุดถามมิตินี้ ปล่อยงบไปที่อื่น |

> **เกณฑ์เหล่านี้เป็นค่าที่ผู้พัฒนาตั้งเอง ไม่ได้มาจากข้อมูล**
> รายงานตรวจสอบเตือนเรื่อง `High/Low quadrant ไม่มีจุดตัด` ว่าผลจะเปลี่ยนตามเกณฑ์ที่ตั้ง
> ดังนั้นค่าทั้งสามต้อง (ก) เก็บไว้ในที่เดียวเป็นค่าคงที่ที่แก้ได้ (ข) ทำ sensitivity analysis เมื่อมีข้อมูลจริง
> และ (ค) **ไม่แสดงตัวเลขความมั่นใจให้ผู้เรียนเห็นเป็นเปอร์เซ็นต์** เพราะจะอ่านเหมือนคะแนน

## 2.4 การเลือกคำถามถัดไป

คิดเป็น **คิวที่จัดลำดับด้วยคะแนนความคุ้ม** ไม่ใช่ต้นไม้ตัดสินใจตายตัว
เพราะต้นไม้ตายตัวจะระเบิดเป็นสาขานับพันเมื่อมี 6 มิติ × 30 facet

```
priority(item) =
      3.0 × isResolvingContradiction(item)      // คลี่ความขัดแย้งมาก่อนทุกอย่าง
    + 2.0 × uncertaintyOfTarget(item)           // มิติที่ยังไม่ชัดได้ก่อน
    + 1.5 × isUntouchedFacet(item)              // facet ที่ยังไม่เคยถาม
    + 1.0 × isDifferentiating(item)             // ข้อที่แยกสองทางที่คะแนนใกล้กัน
    + 0.8 × exploreBonus(item)                  // โควตาสำรวจทางอื่น §2.7
    − 2.0 × isPrunedBranch(item)
    − 1.0 × formatFatigue(item)                 // ถามรูปแบบเดิมติดกันเกินสองข้อ
```

`uncertaintyOfTarget` = `1 − confidence[d]` และเมื่อสองมิติคะแนนใกล้กันภายใน tie band
ข้อที่แยกสองมิตินั้นจะได้ `isDifferentiating = 1`

**tie band** คำนวณจาก
```
tieBand = 1.2 × pooledSem        โดย pooledSem = sd รวม / √n
```
ถ้าสองมิติต่างกันน้อยกว่านี้ ถือว่า **ยังแยกไม่ได้** ต้องถามต่อ หรือรายงานสถานะ *low differentiation*
รายงานตรวจสอบชี้ว่า `Top 3 บังคับแม้คะแนนเสมอหรือแบน` เป็นข้อผิด — จึงต้องมี tie band และสถานะนี้

## 2.5 ลำดับชั้นคำถาม

ผู้ใช้เสนอ 5 ชั้น เอกสารนี้ใช้ **5 ชั้นเดิม แต่เพิ่มชั้น 0 และเปลี่ยนความหมายของชั้น 4**

| ชั้น | ชื่อ | ตอบคำถามอะไร | ให้คะแนนไหม |
|---|---|---|---|
| **L0** | ปรับจังหวะ | ผู้เรียนอยู่ขั้นไหนของการตัดสินใจ (CIP) · ชอบรูปแบบกิจกรรมแบบไหน | ไม่ |
| **L1** | สำรวจกว้าง | มิติใดควรถามต่อ | ใช่ (น้ำหนัก 0.5) |
| **L2** | สำรวจมิติ | คะแนนของมิตินั้นเท่าไร | ใช่ (1.0) |
| **L3** | แยก facet | ชอบ *อะไรกันแน่* ในมิตินั้น | ใช่ (1.0) |
| **L4** | ตรวจความสอดคล้อง | คำตอบก่อนหน้าทนต่อการถามคนละรูปแบบไหม | ใช่ (0.8) |
| **L5** | เจาะลึก | ในสิ่งที่ชอบชัดแล้ว ชอบระดับไหนและในบริบทไหน | ใช่ (0.6) |

**เหตุผลที่เพิ่ม L0** เพราะจำนวนคำถามที่เหมาะสมต่างกันตามความพร้อม
ผู้เรียนที่ยังไม่เริ่มคิดเลยควรได้ L1 กว้าง ๆ หลายข้อ ส่วนผู้ที่เกือบตัดสินใจแล้วควรข้ามไป L3/L4 เร็วขึ้น
L0 มี 3 ข้อ ถามก่อนเสมอ และ **ไม่เข้าคะแนนมิติ**

**เหตุผลที่เปลี่ยน L4** ผู้ใช้เสนอว่า L4 = "ตรวจว่าคำตอบสอดคล้องกัน"
เอกสารนี้ตีความให้แคบลงและวัดได้: **ถามโครงสร้างเดิมด้วยรูปแบบคำถามที่ต่างออกไป**
(กิจกรรม → สถานการณ์ หรือ กิจกรรม → ข้อกลับด้าน)
ถ้าคำตอบยังไปทางเดิม แปลว่าทนต่อรูปแบบ ถ้าพลิก แปลว่าอาจติดถ้อยคำ ไม่ใช่ติดความชอบ

## 2.6 เส้นทางไป IRT — และทำไมยังไม่ใช้ตอนนี้

รายงานตรวจสอบระบุเป็น **ข้อวิกฤต** ว่าเอกสารทีมเสนอสูตร 2PL กับ CAT ทันที
ทั้งที่ 2PL เป็นโมเดลทวิภาค ขณะที่คำถามเราเป็นมาตร 5 ระดับ และยังไม่มีคลังข้อที่ปรับเทียบแล้ว

**ระบบนี้จึงเป็น rule-based ทั้งหมด** และตั้งใจให้กฎอ่านออกได้ด้วยตาเปล่า

เส้นทางไป IRT ที่ถูกต้องตามรายงานและ `Academic References & Standards.md`:

| ขั้น | ต้องมีอะไรก่อน |
|---|---|
| 1 · IOC | ผู้เชี่ยวชาญ 3–5 คนให้คะแนนความสอดคล้องข้อกับโครงสร้าง |
| 2 · ทดลองใช้ | ผู้เรียนจริงจำนวนพอสำหรับประมาณค่าพารามิเตอร์ |
| 3 · Cronbach's α รายมิติ | ข้อในมิติเดียวกันต้องมีหลายข้อ (คลังนี้ให้ 8–12) |
| 4 · CFA | ทดสอบว่า 6 มิติแยกกันจริงในข้อมูลไทย |
| 5 · Rasch rating-scale / GRM / GPCM | โมเดลที่ถูกต้องสำหรับมาตรหลายระดับ ไม่ใช่ 2PL |
| 6 · CAT | ทำได้หลังคลังปรับเทียบแล้วเท่านั้น |

**สิ่งที่การออกแบบนี้ทำไว้เพื่อรองรับขั้นนั้น**
คลังคำถามเก็บ `facet`, `diagnosticStrength`, `reverseScored`, `sourceType` ไว้ตั้งแต่ต้น
และมี **8–12 ข้อต่อมิติ** ซึ่งเป็นจำนวนขั้นต่ำที่ทำให้ α และ CFA มีความหมาย
คลังเดิม 5 ข้อต่อมิติทำได้แต่คับ

## 2.7 สำรวจทางอื่น — กัน confirmation bias

ข้อกำหนดจากผู้ใช้: แม้ระบบมั่นใจแล้วก็ควรทดสอบทางอื่นเล็กน้อย

**กลไก** `exploreQuota` เริ่มต้นที่ **3 ข้อ** ใช้เมื่อ

1. มิติสูงสุดมี `confidence ≥ 0.75` **และ**
2. มีมิติที่ `n < 3` (ยังแทบไม่ถูกถาม) **หรือ** มิติที่ถูก prune ด้วยหลักฐานเพียง 2 ข้อ

**เลือกมิติไหน** ตามลำดับนี้
1. มิติที่เป็น **คู่ตรงข้ามบนหกเหลี่ยม** ของมิติสูงสุด (R↔S, I↔E, A↔C)
   — เพราะ `holland_riasec_analysis.md` ระบุว่าโปรไฟล์ที่สูงทั้งคู่ตรงข้ามไม่ใช่ความผิดพลาด
   แต่เป็นความสอดคล้องต่ำที่ชี้ไปสาขาบูรณาการ และเป็นกรณีที่ระบบทั่วไปมองข้าม
2. มิติที่ **คะแนนสูงเป็นอันดับถัดไปแต่ยังไม่ถูกสำรวจ**
3. มิติที่ถูก prune เร็วเกินไป

**ทำไมต้องมี** รายงานตรวจสอบเตือนว่ากลุ่ม *ความสนใจต่ำ + ความมั่นใจต่ำ* อาจเป็นเพียงสิ่งที่ผู้เรียน **ยังไม่เคยสัมผัส**
การปิดทางเลือกเพราะเด็กไม่รู้จักมัน คือการลงโทษเด็กที่ไม่มีโอกาส

## 2.8 สิ่งที่ระบบนี้ **ไม่** ทำ

| ไม่ทำ | เหตุผล |
|---|---|
| ไม่แสดงเปอร์เซ็นต์ความเหมาะสม | รายงานตรวจสอบระบุห้าม และผลิตภัณฑ์ไม่แสดงอยู่แล้ว |
| ไม่แสดงตัวเลขความมั่นใจให้ผู้เรียน | จะอ่านเหมือนคะแนนสอบ |
| ไม่หักคะแนนด้วยอุปสรรค | เปลี่ยนความเสียเปรียบเป็น "ความไม่เหมาะสมของบุคคล" |
| ไม่บังคับ top-3 เมื่อคะแนนแบน | ต้องรายงาน *low differentiation* แทน |
| ไม่ใช้ cosine บนคะแนนบวกล้วน | ต้อง centered ก่อน ไม่งั้นคนตอบสูงทุกข้อดูเหมือนทุกอาชีพ |
| ไม่เรียกความมั่นใจว่าทักษะ | ความมั่นใจสูงไม่พิสูจน์ว่าทำได้ |
| ไม่ปิดเส้นทางถาวรจากคำตอบเดียว | ดู [`03-branching-rules.md`](03-branching-rules.md) |
| ไม่ให้โมเดลภาษาเลือกคำถาม | คำถามถัดไปมาจากกฎที่ตรวจสอบได้ ไม่ใช่จากการสร้างข้อความ |

ข้อสุดท้ายสำคัญกับผลิตภัณฑ์นี้เป็นพิเศษ — คำสัญญาคือกลไกกฎเป็นผู้ตัดสิน
ถ้าให้โมเดลเลือกคำถามถัดไป โมเดลจะกลายเป็นผู้กำหนดเส้นทางโดยอ้อม
