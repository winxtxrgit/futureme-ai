## 1 · โครงร่างระดับไฟล์

```
{
  "meta":    { … },        // ที่มา ข้อจำกัด สัญญาอนุญาต
  "scales":  { … },        // สเกล 5 ระดับ สองชุด
  "facets":  { … },        // 30 facet · 5 ต่อมิติ
  "items":   [ … ]         // ตัวข้อ
}
```

ไฟล์นี้ถูก **สร้างด้วยสคริปต์** [`build.py`](build.py) ไม่ใช่แก้มือ
เหตุผลคือ 30 ฟิลด์ × 90 ข้อ แก้มือแล้วไม่สม่ำเสมอแน่ และกติกา 17 ข้อใน §5 จะได้ทำงานเป็น assertion ทุกครั้งที่ build

```
python3 build.py            # เขียน items.json แล้วตรวจ
python3 build.py --check    # ตรวจไฟล์ที่มีอยู่โดยไม่เขียนทับ
```

### สองสเกล ไม่ใช่หนึ่ง

| `scaleId` | ใช้กับ | จุด 1 → 5 |
|---|---|---|
| `scale5-preference` | ข้อความสนใจทั้งหมด | ไม่ชอบอย่างยิ่ง → ชอบอย่างยิ่ง |
| `scale5-confidence` | `self-efficacy` เท่านั้น | ยังทำไม่ได้เลย → ทำได้ดีแน่นอน |

`scale5-preference` ใช้ค่าและถ้อยคำเดียวกับ `03_WebApp/Pre_Present/data/questions.json` ทุกตัวอักษร
เพื่อให้ข้อจากคลังนี้ย้ายเข้าแอปได้โดยไม่ต้องแปลงสเกล

**ต้องมีสองสเกล** เพราะถ้าถามความมั่นใจบนสเกลความชอบ คำว่า "ชอบอย่างยิ่ง" จะกลายเป็น "ทำได้"
ซึ่งเป็นการปน interest กับ ability ที่รายงานตรวจสอบเชิงจิตมิติระบุเป็นข้อผิดระดับสูงพอดี

## 2 · ฟิลด์ของข้อ

### กลุ่มระบุตัวตน

| ฟิลด์ | ชนิด | บังคับ | ความหมาย |
|---|---|---|---|
| `id` | string | ✓ | `{PREFIX}-{DIM}-{NN}` เช่น `INT-R-01` · เสถียรตลอดไป ห้ามนำกลับมาใช้ซ้ำ |
| `dimension` | `R I A S E C` หรือ `null` | ✓ | `null` = ไม่สังกัดมิติ (`values-ranking` · `open-text`) |
| `facet` | string \| null | ✓ | คีย์จาก §4 · `null` เฉพาะข้อระดับมิติกว้าง |
| `probeType` | enum 12 ค่า | ✓ | ตาม [`../06-taxonomy.md`](../06-taxonomy.md) §6.1 |
| `level` | `L0`–`L5` | ✓ | ตำแหน่งในลำดับชั้น |

### กลุ่มการให้คะแนน

| ฟิลด์ | ชนิด | บังคับ | ความหมาย |
|---|---|---|---|
| `scoring` | `"dimension"` \| `"tiebreak"` \| `"none"` | ✓ | `"none"` = ห้ามเข้าสมการคะแนนโดยเด็ดขาด |
| `direction` | `"positive"` \| `"reverse"` | ✓ เมื่อ `scoring:"dimension"` | `reverse` → `score = 6 − raw` |
| `diagnosticWeight` | 0.0–1.0 | ✓ เมื่อให้คะแนน | น้ำหนักใน `coverage` · 1.0/0.7/0.6 ตาม §6.1 |
| `diagnosticStrength` | `"high"` \| `"medium"` \| `"low"` | ✓ | เฉพาะ `high` ที่ใช้เป็นหลักฐานปิดสาขาได้ ([`../03-branching-rules.md`](../03-branching-rules.md) §3.3) |
| `responseFormat` | `"scale5"` \| `"choice"` \| `"pair"` \| `"rank3of6"` \| `"text"` | ✓ | |
| `scaleId` | string \| null | ✓ | `null` เมื่อ `responseFormat` ไม่ใช่ `scale5` |
| `options` | array \| absent | เมื่อไม่ใช่ `scale5` | แต่ละตัวมี `value` · `label{en,th}` · `maps` |
| `maps` | object | ในตัวเลือก | มิติ → น้ำหนัก เช่น `{"E":0.5,"C":0.5}` · `{}` = ไม่ให้คะแนน |

ข้อ `scenario` มี `dimension: null` แต่ `scoring: "dimension"` — มิติที่ขยับมาจาก `maps` ของตัวเลือกที่ผู้เรียนเลือก
ไม่ใช่จากตัวข้อ กติกา 3 ใน §5 จึงยอมรับสองรูปแบบนี้

### กลุ่มการควบคุมการแตกสาขา

| ฟิลด์ | ชนิด | บังคับ | ความหมาย |
|---|---|---|---|
| `purpose` | `"measure"` \| `"clarify"` \| `"validate"` \| `"explore"` \| `"context"` | ✓ | บทบาทในลูป |
| `triggers` | array \| absent | | เงื่อนไขที่ทำให้ข้อนี้เข้าคิว ดู §3 |
| `prerequisiteOf` | string[] \| absent | | `id` ของข้อที่ต้องถูกถามก่อน |
| `mutuallyExclusiveWith` | string[] \| absent | | ถ้าข้อนี้ถูกถาม ข้อในรายการจะไม่ถูกถามอีก (ข้อที่ซ้ำความหมาย) |
| `reverseCounterpart` | string \| absent | | `id` ของข้อคู่กลับด้าน — ใช้ตรวจ `reverse-fail` |
| `budgetKey` | string | คำนวณ | `{dimension}:{facet}:{probeType}` — ไม่เก็บในไฟล์ ระบบสร้างเอง |

### กลุ่มที่มาและความน่าเชื่อถือ

| ฟิลด์ | ชนิด | บังคับ | ความหมาย |
|---|---|---|---|
| `sourceType` | `validated-external` \| `adapted-18rest` \| `researcher-written` \| `exploratory` | ✓ | |
| `sourceRef` | string \| null | ✓ | คีย์อ้างอิงใน `meta.references` · `null` เฉพาะ `researcher-written` |
| `licence` | string | ✓ | `"CC BY 4.0"` · `"project"` · `"restricted-do-not-use"` |
| `validationStatus` | `"none"` | ✓ | **ทุกข้อในคลังนี้เป็น `"none"`** จนกว่าจะมีข้อมูลจริง |
| `psychometrics` | object \| null | ✓ | `null` ตลอดจนกว่าจะคำนวณได้ · ห้ามเติมค่าที่ไม่ได้คำนวณเอง |

### กลุ่มการแสดงผลและความเหมาะสม

| ฟิลด์ | ชนิด | บังคับ | ความหมาย |
|---|---|---|---|
| `text` | `{en, th}` | ✓ | ภาษาไทยเป็นภาษาต้นฉบับ อังกฤษเป็นคำแปล |
| `help` | `{en, th}` \| absent | | คำอธิบายเพิ่ม |
| `tierScope` | array | ✓ | `LOWER_SECONDARY` · `UPPER_SECONDARY` · `VOCATIONAL` |
| `readingLevel` | `"m1"` \| `"m4"` | ✓ | `m1` = ใช้ได้กับ ม.1 ขึ้นไป |
| `sensitivity` | `"none"` \| `"family"` \| `"money"` \| `"body"` | ✓ | ข้อที่ไม่ใช่ `none` ต้องข้ามได้ |
| `desirabilityMatched` | boolean | ✓ เมื่อ `probeType:"forced-choice"` | ต้องเป็น `true` ถึงจะใช้ได้ |
| `culturalNote` | string \| absent | | ข้อสังเกตด้านบริบทไทยที่ต้องระวังเวลาแปลหรือปรับ |
| `reviewFlags` | string[] | ✓ | ปัญหาที่ยังไม่แก้ · array ว่างได้ ต้องมีฟิลด์ |

### กลุ่มเฉพาะชนิด

| ฟิลด์ | ใช้กับ | ความหมาย |
|---|---|---|
| `desirabilityAxes` | `forced-choice` | แกนที่จับคู่ให้เท่ากัน — `prestige` · `expected-pay` · `job-security` · `familiarity` |
| `integratesPair` | `integration` | คู่ตรงข้ามที่ข้อนี้รวมเข้าด้วยกัน เช่น `["R","S"]` |
| `integrativeFields` | `integration` | สาขาบูรณาการที่คู่นี้ชี้ไป — ใช้อธิบาย ไม่ใช่ผลลัพธ์ |
| `slots` | ข้อ `purpose:"clarify"` | ชื่อช่องเติมใน `text` เช่น `["A","B"]` ระบบเติมจากข้อที่ผู้เรียนตอบไปแล้ว |
| `hypothesis` | ในตัวเลือกของข้อ clarify | สมมติฐาน H1–H6 ที่ตัวเลือกนั้นยืนยัน |

**รวม 30 ฟิลด์ที่นิยามไว้** ในสี่กลุ่มข้างบน — ไม่นับ `maps` ที่อยู่ภายในตัวเลือก และ `budgetKey` ที่ระบบคำนวณเอง
บวกฟิลด์เฉพาะชนิดอีก 5 ตัวในตารางนี้ · ตามที่โจทย์ขอไม่น้อยกว่า 20

**ฟิลด์ที่บังคับให้มีแม้ค่าเป็นว่าง** — `validationStatus` · `psychometrics` · `reviewFlags`
เพราะการ **ไม่มี** ฟิลด์เปิดช่องให้คนอ่านสมมติว่ามีค่า การมีฟิลด์ที่เป็น `none`/`null` ปิดช่องนั้น

## 3 · รูปแบบ `triggers`

```json
"triggers": [
  { "on": "response", "item": "INT-I-01", "values": [5] },
  { "on": "dimensionHigh", "dimension": "I", "minScore": 4.0 },
  { "on": "contradiction", "kind": "within-dimension", "dimension": "I" },
  { "on": "uncertain", "item": "INT-I-01" },
  { "on": "tie", "dimensions": ["I", "A"] },
  { "on": "oppositePairHigh", "pair": ["R", "S"] }
]
```

หลายเงื่อนไขในอาเรย์เดียวคือ **หรือ** — ข้อเข้าคิวถ้าเงื่อนไขใดเงื่อนไขหนึ่งเป็นจริง
ต้องการ **และ** ให้ใช้ `prerequisiteOf` ร่วม

ตัวจัดตารางเป็นตัวตัดสินสุดท้ายว่าข้อในคิวข้อไหนถูกถาม — `triggers` ทำให้ข้อ **มีสิทธิ์** ไม่ใช่ **ถูกถามแน่**

## 5 · กติกาที่ตรวจได้ด้วยเครื่อง

ทั้งหมดนี้ควรเป็นเทสต์เมื่อคลังถูกนำเข้าโค้ด

| # | กติกา |
|---|---|
| 1 | `id` ไม่ซ้ำ |
| 2 | ทุก `facet` ที่อ้างอิงมีอยู่ใน `facets` |
| 3 | `scoring:"dimension"` → ต้องมี `direction` · `diagnosticWeight` และมี `dimension` **หรือ** ทุกตัวเลือกมี `maps` |
| 4 | `scoring:"none"` → ห้ามมี `diagnosticWeight` |
| 5 | `probeType:"self-efficacy"` → `scoring` ต้องเป็น `"none"` |
| 6 | `probeType:"forced-choice"` → `desirabilityMatched:true` และ `scoring:"tiebreak"` |
| 7 | `probeType:"integration"` → `scoring:"none"` และ `dimension:null` |
| 8 | ทุกมิติมีข้อ `scoring:"dimension"` ≥ 8 ข้อ |
| 9 | ทุกมิติมีข้อ `direction:"reverse"` ≥ 2 ข้อ |
| 10 | ทุก facet มีข้อ ≥ 1 ข้อ |
| 11 | `reverseCounterpart` ชี้ไปข้อที่มีอยู่ และชี้กลับมาหากันสองทาง |
| 12 | `sourceType:"adapted-18rest"` → `sourceRef` ต้องไม่เป็น `null` และ `licence:"CC BY 4.0"` |
| 13 | ไม่มีข้อใดมี `licence:"restricted-do-not-use"` |
| 14 | ทุกข้อมี `text.th` และ `text.en` ที่ไม่ว่าง |
| 15 | `validationStatus` ทุกข้อเป็น `"none"` · `psychometrics` ทุกข้อเป็น `null` |
| 16 | `triggers` ทุกตัวที่อ้าง `item` ชี้ไป `id` ที่มีอยู่ |
| 17 | ผลรวม `maps` ในหนึ่งตัวเลือกไม่เกิน 1.0 |

กติกา 13 และ 15 คือกติกาที่กันการอ้างเกินจริง ซึ่งเป็นความเสี่ยงหลักของงานนี้

## 6 · เรื่องสัญญาอนุญาตที่ต้องไม่พลาด

**ห้ามคัดลอกข้อจากมาตรที่มีลิขสิทธิ์** — Strong Interest Inventory · Self-Directed Search
ทั้งสองเป็นเครื่องมือเชิงพาณิชย์ที่มีลิขสิทธิ์ การนำข้อมาใส่คลังนี้ผิดกฎหมายและผิดจริยธรรมวิชาชีพ

**สิ่งที่ทำได้**
- ใช้ **โครงสร้างทฤษฎี** RIASEC — ทฤษฎีไม่มีลิขสิทธิ์
- ใช้ข้อจาก **18REST** (CC BY 4.0) โดยให้เครดิตตามสัญญาอนุญาต
- ใช้ **โครงร่างเชิงแนวคิด** จาก O*NET Interest Profiler (สาธารณสมบัติของรัฐบาลสหรัฐ) พร้อมระบุที่มา
- **เขียนข้อขึ้นใหม่เอง** ตามคำนิยามของโครงสร้าง — เป็นวิธีที่ใช้กับข้อส่วนใหญ่ในคลังนี้

**สิ่งที่ห้ามอ้าง** ค่าความเที่ยง ความตรง หรือค่าสถิติใด ๆ ที่ทีมไม่ได้คำนวณจากข้อมูลของตัวเอง
การอ้างค่า α ของ 18REST ว่าเป็นค่าของชุดนี้ **เป็นการอ้างเท็จ** แม้ข้อจะดัดแปลงมาจากที่นั่น

## 7 · องค์ประกอบของคลังรุ่นแรก

ตัวเลขทั้งหมดนี้มาจาก `python3 build.py` โดยตรง ไม่ใช่การนับมือ

| ชนิด | จำนวน | ให้คะแนนมิติ |
|---|---|---|
| `interest-activity` | 30 | ✓ (น้ำหนัก 1.0) |
| `interest-facet` | 12 | ✓ (น้ำหนัก 1.0) |
| `reverse-keyed` | 12 | ✓ (กลับค่า) |
| `intensity` | 6 | ✓ (น้ำหนัก 0.6) |
| `scenario` | 5 | ✓ 3 ข้อ (น้ำหนัก 0.7) · 2 ข้อเป็นข้อคลี่คลาย ไม่ให้คะแนน |
| `forced-choice` | 6 | △ ตัดสินเสมอเท่านั้น |

| `experience` | 6 | ✗ |
| `integration` | 3 | ✗ |
| `environment` | 1 | ✗ |
| `values-ranking` | 1 | ✗ |
| `open-text` | 2 | ✗ |
| **รวม** | **90** | ให้คะแนนมิติ 63 · ตัดสินเสมอ 6 · ไม่ให้คะแนน 21 |

**ต่อมิติ** ข้อที่ให้คะแนน 10 ข้อ (L2 ห้า · L3 สอง · กลับด้าน สอง · เข้ม หนึ่ง)
ครบเงื่อนไข 8–12 ข้อต่อมิติที่ทำให้ Cronbach's α และ CFA มีความหมาย **เมื่อเก็บข้อมูลได้**

**ต่อ facet** ครบทั้ง 30 facet อย่างน้อย 1 ข้อ — ตรวจด้วยกติกา 10

**ที่ยังขาดและรู้ตัว**

| ช่องว่าง | ผลกระทบ | แผน |
|---|---|---|
| ยังไม่มีข้อ `validated-external` เลย | อ้างความเที่ยงจากภายนอกไม่ได้ | หามาตรที่มีสัญญาอนุญาตเปิด (O*NET IP เป็นตัวเลือกหลัก) |
| การจับคู่ความพึงปรารถนาของ `forced-choice` เป็นการตัดสินของทีม | ข้ออาจยังลำเอียง | ให้ครูแนะแนว 5 คนให้คะแนน 4 แกน แล้วคัดคู่ที่คะแนนต่างกันออก |
| ยังไม่มี IOC จากผู้เชี่ยวชาญ | ความตรงเชิงเนื้อหายังไม่มีหลักฐาน | ขั้นแรกของแผนตรวจสอบใน [`../08-implementation-notes.md`](../08-implementation-notes.md) |
| `INT-A-01` · `INT-C-R1` · `INT-A-R1` · `INT-S-06` มี facet คาบเกี่ยว | อาจโหลดข้ามมิติ | อยู่ใน `reviewFlags` ของแต่ละข้อ รอ CFA |
| พจนานุกรม facet สำหรับ `open-text` ยังไม่ได้เขียน | `OPN-01` ยังไม่ทริกเกอร์อะไรได้ | ต้องทำก่อนเปิดใช้ข้อ open-text จริง |
