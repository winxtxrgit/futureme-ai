## 6.2 รายละเอียดแต่ละชนิด

### 1 · `interest-activity` — ข้อกิจกรรมมาตรฐาน

กระดูกสันหลังของแบบสำรวจ รูปประโยคเดียวกับ 18REST: กิจกรรมรูปธรรมหนึ่งอย่าง ไม่มีคำตัดสินค่า

```
"ซ่อมจักรยานหรือเครื่องยนต์มอเตอร์ไซค์"                    R.hardware
"อ่านบทความหรือหนังสือเกี่ยวกับการค้นพบทางวิทยาศาสตร์"      I.research
```

**กติกาการเขียน**
- กิจกรรม **หนึ่ง** อย่างต่อข้อ — "ซ่อมและออกแบบเครื่องยนต์" วัดสองมิติ ตีความไม่ได้
- ไม่มีชื่ออาชีพ — "เป็นหมอ" นำเรื่องสถานะเข้ามา ไม่ได้วัดความสนใจ
- ไม่มีคำที่บอกว่าดี/เท่/มั่นคง
- ต้องเป็นสิ่งที่เด็กไทยอายุ 14–18 นึกภาพออก **โดยไม่ต้องเคยทำ**
- ภาษาไทยต้องเป็นภาษาพูดที่นักเรียนใช้จริง ไม่ใช่ภาษาเอกสารราชการ

### 2 · `interest-facet` — ข้อแยก facet

เหมือนชนิด 1 แต่จงใจแคบ ยิงหลังจากผู้เรียนตอบ 5 เพื่อหาว่าชอบส่วนไหนของมิติ

```
มิติ I ตอบ 5 → แยกด้วย
"ดูตารางตัวเลขแล้วหาว่ามีแบบแผนอะไรซ่อนอยู่"     I.data
"เครื่องพัง แล้วคุณเป็นคนหาว่าพังเพราะอะไร"       I.diagnose
```

ข้อสองข้อนี้แยก "นักวิเคราะห์ข้อมูล" จาก "ช่างเทคนิคระดับสูง" ซึ่งเป็นสองเส้นทางที่ต่างกันมาก
แต่ **ข้อกว้างระดับมิติแยกไม่ได้เลย**

### 3 · `intensity` — ข้อวัดระดับความเข้ม

ถามว่าความชอบนั้นแรงพอจะยอมแลกอะไรไหม

```
"ถ้าต้องอ่านเรื่องเดิมซ้ำหลายรอบจนกว่าจะเข้าใจ คุณยังอยากทำไหม"
"ถ้างานนี้ต้องทำทุกวันเสาร์ตลอดเทอม คุณยังอยากทำไหม"
```

**น้ำหนัก 0.6** เพราะข้อพวกนี้ปนความอึดเข้ามา ซึ่งไม่ใช่ความสนใจล้วน

**สองข้อที่การจำลองบังคับให้แก้**

1. **ข้อ `intensity` ไม่เข้าสมการ `consistency`** — คำตอบของข้อพวกนี้ตั้งใจให้ต่ำกว่าข้อความสนใจ
   การนับมันเป็นการกระจายทำให้ข้อ L5 **ลดความมั่นใจของมิติที่มันกำลังเจาะลึก**
   ค่ามัธยฐานความมั่นใจของมิติอันดับ 1 ตกทันทีที่ข้อพวกนี้เข้าถึงได้ ข้อนี้จึงนับเข้า `coverage` อย่างเดียว
2. **ข้อ L5 ถามได้แม้สาขาจะ `satisfied` แล้ว** — เดิมสาขาที่ปิดเพราะมั่นใจพอ จะไม่รับข้อใด ๆ อีก
   แต่เงื่อนไขยิงของ `intensity` คือคะแนน ≥ 4.5 ซึ่งมิตินั้นย่อม `satisfied` ไปแล้วเสมอ
   ผลคือ **ข้อ `intensity` ทั้ง 6 ข้อไม่เคยถูกถามเลยแม้แต่ครั้งเดียวใน 400 เซสชัน**
   ตอนนี้ถามได้ แต่ยังพบไม่บ่อย (0.13 ข้อต่อเซสชัน) ดู [`sim/README.md`](sim/README.md) FIX 8 · FIX 10

### 4 · `scenario` — ข้อสถานการณ์

วางผู้เรียนในสถานการณ์แล้วให้เลือกการกระทำ ตัวเลือกแต่ละตัวแมปไปมิติต่างกัน

```
"งานกลุ่มวิชาวิทยาศาสตร์ ครูให้ทำโครงงานอิสระ คุณอยากรับหน้าที่ไหน"
 ก) ประกอบชิ้นงานและทำให้มันทำงานได้จริง        → R
 ข) หาข้อมูลและออกแบบวิธีทดลอง                  → I
 ค) ทำโปสเตอร์และคลิปให้คนดูเข้าใจง่าย           → A
 ง) ประสานงานทุกคนและคุมให้เสร็จทันเวลา          → E + C
```

**น้ำหนัก 0.7** เพราะการเลือกหน้าที่ในงานกลุ่มปนเรื่องบทบาททางสังคมในห้องเรียนเข้ามาด้วย

**กติกาสำคัญ** ตัวเลือก "ง" ที่แมปสองมิติ ให้ **0.5 กับแต่ละมิติ** ไม่ใช่ 1.0 กับทั้งคู่

### 5 · `reverse-keyed` — ข้อกลับด้าน

**นี่คือช่องว่างที่ใหญ่ที่สุดของคลังปัจจุบัน** — ทั้ง 30 ข้อเป็น `direction: "positive"` ทั้งหมด
ทำให้ไม่มีทางแยก *ผู้ที่ชอบจริง* จาก *ผู้ที่กดเห็นด้วยไปเรื่อย ๆ* (acquiescence bias)

```
INT-C-R1  "ทำงานที่มีขั้นตอนกำหนดไว้ชัดเจนทุกอย่าง"                  → C positive
INT-C-R2  "ทำงานที่ต้องคิดเองทุกวันว่าจะทำอะไร ไม่มีใครบอกขั้นตอน"    → C reverse
```

**การให้คะแนน** `score = 6 − raw` สำหรับ `direction: "reverse"`

**กติกาการเขียนที่ต้องเคร่งครัด**
- ห้ามใช้การเติม "ไม่" ลงในข้อบวก — "ไม่ชอบซ่อมของ" ทำให้เกิดการปฏิเสธซ้อนกับสเกล "ไม่ชอบอย่างยิ่ง" ซึ่งสับสนมากในภาษาไทย
- ต้องเขียนเป็น **กิจกรรมตรงข้ามในเชิงเนื้อหา** ไม่ใช่การปฏิเสธเชิงไวยากรณ์
- ต้องไม่กลายเป็นข้อของมิติอื่นไปเสียเอง — ข้อ C reverse ข้างบนใกล้ A มาก ต้องระวังและตรวจด้วย CFA เมื่อมีข้อมูล

**หน้าที่คู่ขนาน** ถ้าผู้เรียนตอบข้อบวกและข้อกลับด้านไปทางเดียวกัน → `reverse-fail` ใน [`04-contradictions.md`](04-contradictions.md) §4.2
ลดน้ำหนักคำตอบทั้งมิติ นี่เป็นตัวคุมคุณภาพการตอบ **ตัวเดียว** ที่ระบบมี

### 6 · `forced-choice` — เลือกหนึ่งจากสอง

ใช้ **เฉพาะ** ตอนสองมิติต่างกันน้อยกว่า tie band

**ข้อบังคับ** ทุกข้อต้องมี `desirabilityMatched: true` และคู่ตัวเลือกต้องเทียบเท่ากันใน 4 แกน

| แกน | ต้องเท่ากัน |
|---|---|
| เกียรติ / การยอมรับทางสังคม | ✓ |
| รายได้ที่คนทั่วไปคาดว่าจะได้ | ✓ |
| ความมั่นคงของงาน | ✓ |
| ความคุ้นเคยของเด็กไทย | ✓ |

```
✗ ผิด   "เป็นหมอ" vs "ซ่อมมอเตอร์ไซค์"            — ต่างกันทั้ง 4 แกน
✓ ใช้ได้ "จัดของในคลังให้เป็นระบบ" vs "ตรวจใบเสร็จให้ตรงทุกใบ"  — C ทั้งคู่ ใกล้กันทั้ง 4 แกน
✓ ใช้ได้ "เขียนโปรแกรมให้ระบบทำงานถูก" vs "ออกแบบหน้าจอให้คนใช้ง่าย"  — I vs A ใกล้กันทั้ง 4 แกน
```

**คำเตือนจากรายงานตรวจสอบ** การอ้างว่า forced-choice คุม social desirability ได้ **เป็นเท็จ**
ถ้าตัวเลือกไม่ได้จับคู่ความพึงปรารถนา ระบบนี้จึงบังคับให้จับคู่ ไม่ใช่แค่หวัง

**ที่ให้คะแนนได้จำกัด** ผลของ forced-choice เป็นข้อมูล **เชิงเปรียบเทียบ** ไม่ใช่ระดับความชอบ
จึงไม่บวกเข้าคะแนนมิติ แต่ปรับ **ลำดับ** ระหว่างสองมิติที่เสมอกันเท่านั้น

### 7 · `integration` — ข้อบูรณาการคู่ตรงข้าม

ใส่แรงสองอย่างที่ขัดกันเข้าไปในกิจกรรมเดียว ยิงเมื่อพบ `opposite-pair-high`

```
R↔S  "ใช้เครื่องมือและมือของคุณเอง ช่วยให้คนกลับมาเดินได้"
I↔E  "อธิบายงานวิจัยยาก ๆ ให้นักลงทุนเข้าใจว่าทำไมมันคุ้มค่า"
A↔C  "ออกแบบระบบสีและตัวอักษรให้ทุกหน้าของแอปใช้ตรงกันทั้งหมด"
```

**ไม่ให้คะแนนมิติ** ผลของมันตั้งค่า `profileConsistency` และเปิดทั้งสองมิติไว้
ให้คะแนนไม่ได้เพราะข้อเดียวมีสองโครงสร้าง — ซึ่งขัดกติกาการเขียนข้อ 1

### 8 · `self-efficacy` — ความมั่นใจ

```
"คุณคิดว่าตัวเองทำสิ่งนี้ได้ดีแค่ไหน ถ้ามีคนสอนให้"
```

**ห้ามเข้าคะแนนมิติเด็ดขาด** และ **ห้ามเรียกว่าทักษะ**
รายงานตรวจสอบระบุการเรียก self-efficacy ว่า skill เป็นข้อผิดระดับสูง
ความมั่นใจคือการประเมินตนเอง ทักษะต้องมาจากผลงาน เกรด หรือแบบทดสอบ

ถ้อยคำ **"ถ้ามีคนสอนให้"** อยู่ในนั้นตั้งใจ — มันเปลี่ยนคำถามจาก "เก่งอยู่แล้วไหม" เป็น "เรียนรู้ได้ไหม"
ซึ่งเป็นคำถามที่ถูกต้องสำหรับคนที่ยังไม่เคยเรียนเรื่องนี้

### 9 · `experience` — เคยได้ลองไหม

```
"เคยได้ลองทำสิ่งนี้จริง ๆ ไหม"
 ก) เคย และได้ทำหลายครั้ง
 ข) เคยครั้งเดียวสองครั้ง
 ค) ไม่เคย แต่อยากลอง
 ง) ไม่เคย และไม่คิดจะลอง
```

**นี่คือข้อที่ทำให้ระบบนี้ต่างจากแบบวัดความสนใจทั่วไป**

คำตอบ "ค" เปลี่ยนความหมายของ "ไม่แน่ใจ" ทั้งหมด: มันไม่ใช่ความไม่ชอบ เป็น **ช่องว่างประสบการณ์**
ผู้เรียนคนนี้ควรได้ข้อเสนอให้ไปลอง ไม่ใช่ถูกตัดออก

คำตอบ "ก" เพิ่มความน่าเชื่อถือของคำตอบสเกลในกลุ่มเดียวกัน — คนที่เคยทำแล้วบอกว่าชอบ หนักกว่าคนที่ไม่เคยทำ
(บันทึกเป็น `evidenceQuality` ไม่ใช่บวกคะแนน)

### 10 · `environment` — สภาพแวดล้อมการทำงาน

```
"งานเดิมนี้ แต่เปลี่ยนที่ทำ อันไหนที่คุณยังอยากทำ"
 ก) คนเดียวเงียบ ๆ   ข) ทีมเล็ก   ค) คนเยอะตลอดเวลา   ง) ไม่อยากทำเลย
```

ใช้แยก H3 ใน [`04-contradictions.md`](04-contradictions.md) §4.3 ขั้นที่ 2
ไม่ให้คะแนนมิติ แต่ใช้จัดเรียงเส้นทางที่มีสภาพแวดล้อมตรงกันขึ้นก่อน

### 11 · `values-ranking` — ค่านิยมในการทำงาน

ถามครั้งเดียวตอนต้น (L1) ให้เลือก 3 อย่างที่สำคัญที่สุดจาก 6 ตาม Super

```
ความมั่นคง · รายได้ · ความอิสระ · การได้ช่วยคน · การได้เรียนรู้ตลอด · การได้อยู่ใกล้บ้าน
```

**ไม่ให้คะแนนมิติ** และ **ไม่ใช้กรองเส้นทางออก** — ใช้จัดเรียงข้อมูลที่แสดงในแต่ละเส้นทาง
เช่นผู้ที่เลือก "ใกล้บ้าน" จะเห็นข้อมูลระยะทางและการเดินทางเด่นขึ้น (ต่อกับชุดข้อมูล 77 จังหวัด)

**เหตุผลที่ไม่กรอง** ค่านิยมของคนอายุ 14 เปลี่ยนได้ และการกรองด้วยค่านิยมจะตัดทางที่เด็กไม่รู้ว่ามีอยู่

### 12 · `open-text` — ข้อความอิสระ

```
"เล่าเรื่องอะไรก็ได้ที่คุณทำแล้วรู้สึกภูมิใจ ไม่จำเป็นต้องเกี่ยวกับเรียน"
```

**ไม่ให้คะแนน** และ **ไม่ให้ LLM ตัดสิน**
ใช้สองอย่าง

1. **จับคำที่แมปกับ facet** ด้วยพจนานุกรมคำที่กำหนดไว้ล่วงหน้า → ทริกเกอร์เปิดสาขากลับ ([`03-branching-rules.md`](03-branching-rules.md) §3.4 ข้อ 2)
2. **ส่งต่อให้ครูแนะแนว** เป็นข้อความดิบ ไม่ผ่านการสรุป

การจับคำต้องเป็นการแมปที่ตรวจสอบได้ ถ้าไม่พบคำที่รู้จัก **ระบบไม่เดา** — ตรงตามหลักของผลิตภัณฑ์

## 6.3 สัดส่วนที่ตั้งใจในหนึ่งเซสชัน

จาก 34 ข้อสูงสุด

| ชนิด | จำนวนที่คาด | หมายเหตุ |
|---|---|---|
| `values-ranking` | 1 | คงที่ ตอนต้น |
| `open-text` | 1–2 | ต้นและท้าย |
| `interest-activity` | 12–14 | แกนหลัก ครบ 6 มิติ |
| `interest-facet` | 4–8 | ตามจำนวนสาขาที่เจาะ |
| `reverse-keyed` | 3–4 | **อย่างน้อย 1 ข้อในมิติอันดับสูงสุด** |
| `scenario` | 2–3 | |
| `self-efficacy` | 2–3 | เฉพาะมิติที่คะแนนสูง |
| `experience` | 2–4 | เฉพาะที่ตอบ 3 หรือคะแนนสูง |
| `intensity` | 0–2 | เฉพาะสาขาที่เจาะลึก |
| `environment` · `forced-choice` · `integration` | 0–3 | ตามเงื่อนไข |

**ข้อบังคับที่เข้มที่สุด** ต้องมี `reverse-keyed` อย่างน้อย 1 ข้อ **ในมิติที่ผู้เรียนได้คะแนนสูงสุด**
เพราะมิตินั้นคือมิติที่จะถูกใช้ตัดสิน และเป็นมิติที่ acquiescence bias ทำให้ผิดได้มากที่สุด
กฎนี้ยิงก่อนเงื่อนไขหยุดผลได้ลดน้อยเสมอ

**ข้อยกเว้นสองข้อที่การจำลองบังคับให้เพิ่ม**

1. **ไม่บังคับเมื่อมิติอันดับสูงสุดมีสถานะ `genuinely-uncertain` หรือ `unresolved-mixed`**
   เพราะไม่มีข้อสรุปให้ปกป้อง — และเมื่อสถานะเป็นแบบนั้น ตัวเลือกข้อในมิตินั้นถูกปิดไปแล้ว
   เดิมกฎนี้เรียกร้องข้อที่ตัวจัดตารางไม่มีวันส่งให้ ทำให้ `should_stop` ค้าง
   และ **23% ของเซสชันวิ่งไปชนเพดาน 34 ข้อโดยไม่จำเป็น**
2. **ไม่บังคับเมื่อชนเพดาน 34 ข้อ** เพราะมิติอันดับสูงสุดเปลี่ยนได้จากคำตอบข้อสุดท้าย
   จึงมีกรณีที่ไม่เหลือที่ว่างให้ทำตามกฎ — เกิดราว 0.1% ของเซสชัน และรายงานไว้ ไม่ซ่อน
