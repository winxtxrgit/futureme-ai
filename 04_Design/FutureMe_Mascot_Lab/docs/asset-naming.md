# Asset naming

One convention across SVG, Rive and 3D, so a state can be traced from product
code to art file without a lookup table.

```
futureme_mascot_<category>_<state>.<ext>
```

Lowercase, underscores only. State ids come from `mascot.js`; hyphens in the id
become underscores in the filename (`not-okay` → `not_okay`).

## Categories

| Category | Meaning | Example |
|---|---|---|
| `emotion` | Full body, five levels, idle pose | `futureme_mascot_emotion_very_happy.svg` |
| `face` | Head crop of the same five levels, for the questionnaire | `futureme_mascot_face_very_happy.svg` |
| `pose` | Full body, default friendly face | `futureme_mascot_pose_point_left.svg` |
| `view` | Turnaround, for modelling reference | `futureme_mascot_view_three_quarter.svg` |

## Other formats

Same stem, different extension and container:

| Format | Naming |
|---|---|
| Rive | `futureme_mascot.riv`, one artboard, states named `smile`, `point_left`, … |
| Lottie | `futureme_mascot_celebrate.json` — one clip per file |
| GLB | `futureme_mascot.glb`, animation clips named `pose_wave`, `pose_sit`, … |
| Raster fallback | `futureme_mascot_emotion_smile@2x.webp` |

Rive state names and GLB clip names use the same state ids as the SVG files, so
`pose` in product code selects the right thing in every format.

## Sizes

Export targets from `SKILL.md`, matching the `SIZES` table in `mascot.js`:

| Key | px | Used for |
|---|---|---|
| `xs` | 64 | inline icon |
| `sm` | 96 | card mascot, questionnaire option |
| `md` | 200 | card mascot, empty state |
| `lg` | 300 | interview companion |
| `xl` | 440 | hero |

SVG is resolution-independent, so these are layout widths rather than export
sizes. They matter for raster fallbacks and for checking legibility: emotion has
to read at 64–96 px, which is why those sizes use the `face` crop.

## Rules

- Transparent background, always. No baked-in background plates.
- No text inside the art.
- Never duplicate the character per page. One system, state variations.
- A new state means a new id in `mascot.js` first, then the file — not the
  other way round.
